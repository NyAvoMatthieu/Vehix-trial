### Point technique clarifié pour la Partie 4
`Trajet::boot()` calcule toujours `odo_end` comme un **compteur cumulatif réel**, quel que soit le mode de saisie (`odometer` ou `trajet`) — jamais une distance brute. `Trajet::getLastOdometer($vehiculeId)` existe déjà et fait exactement ce calcul (dernier `odo_end` connu, trié par `heure_arrivee`).

**Conséquence** : l'accesseur `Vehicule::kilometrage_actuel` (Partie 4) réutilise cette méthode plutôt que de lire `km_arrivee` directement :

```php
public function getKilometrageActuelAttribute(): int
{
    return (int) (\App\Models\Trajet::getLastOdometer($this->id) ?? $this->mileage ?? 0);
}
```

### Évolutions de cette session

**1. Option "Autre…" dans le catalogue (Create.vue / Edit.vue)** — patch fourni
- Pas de nouvelle route : le nouveau type est créé directement dans `store()`/`update()`, dans la transaction existante (rollback automatique si la maintenance échoue).
- Nouveau champ de formulaire `nouveau_type_nom` (validation `nullable|string|max:255`) + méthode privée `resolveInterventionType()` dans `MaintenanceController` : réutilise un type du même nom (insensible à la casse) ou le crée avec `actif = true`. **Pas de validation admin.**
- Côté Vue : valeur sentinelle `'other'` dans le `<select>` (l'ancien `<option value=0>` produisait la chaîne `"0"`, donc le test `=== 0` ne marchait jamais) ; `form.transform()` remplace `'other'` par `null` avant envoi.
- Un type créé ainsi n'a **aucun intervalle** → il ne génère aucune échéance tant que l'admin n'a pas renseigné `intervalle_km`/`intervalle_jours` dans le catalogue.
- À corriger dans `Create.vue` : le bouton "Retour en haut" utilise `window.scrollTo` directement dans le template (inaccessible) → remplacer par une fonction `scrollTop()` définie dans le script.
- Cas non traité : un type **désactivé** de même nom est réutilisé sans être réactivé.

**2. Auto-validation à la création (option 1 choisie par l'utilisateur)**
- Dans `store()`, après la création de la maintenance et de ses pièces : `validated_at = now()`, `validateur_id = auth()->id()`, puis `MaintenanceIntervalleService::synchroniserApresMaintenance()`.
- Conséquence : la maintenance est verrouillée dès sa création (`isValidee()` bloque modification et suppression), et le bouton "Valider" de `Show.vue` devient inutile (à masquer/retirer si besoin).
- ⚠️ `date_fin` est `nullable` dans la validation de `store()` mais requise à la validation → à vérifier que l'auto-validation ne laisse pas `date_fin` vide (le formulaire `Create.vue` la marque `required`).

**3. Champ contact du garage — `PhoneInput.vue`** (nouveau composant)
- Remplace le `TextInput` de `garage_contact` dans `Create.vue` et `Edit.vue` : `<PhoneInput id="garage_contact" v-model="form.garage_contact" required />`.
- Version finale : **détection automatique du pays** (sans `<select>`) via `libphonenumber-js/min` (`npm install libphonenumber-js`, puis `npm run build`).
  - Numéro local (`034 12 345 67`) → interprété comme malgache (pays par défaut `MG`) ; numéro `+33…` → pays détecté d'après l'indicatif ; drapeau emoji affiché (🌐 si ambigu, ex. `+1`).
  - Formatage au fil de la frappe ; normalisation en format international à la sortie du champ (`+261 34 12 345 67`). C'est cette chaîne qui est envoyée : **aucun changement backend/BDD**.
  - Numéro invalide → message rouge + `setCustomValidity` (bloque l'envoi ; retirer cette ligne pour ne jamais bloquer).
  - Anciens contacts sans indicatif (Edit) : reconnus comme malgaches et convertis au prochain enregistrement.
- Validation serveur optionnelle proposée : `'garage_contact' => ['required','string','max:100','regex:/^\+\d{1,3}\s\d[\d\s]{5,14}$/']`.
- Limite : drapeaux en emoji, mal rendus sur certains systèmes (lettres "MG" à la place).
