### Point technique clarifié pour la Partie 4
`Trajet::boot()` calcule toujours `odo_end` comme un **compteur cumulatif réel**, quel que soit le mode de saisie (`odometer` ou `trajet`) — jamais une distance brute. `Trajet::getLastOdometer($vehiculeId)` existe déjà et fait exactement ce calcul (dernier `odo_end` connu, trié par `heure_arrivee`).

**Conséquence** : l'accesseur `Vehicule::kilometrage_actuel` (Partie 4) a été corrigé pour réutiliser cette méthode plutôt que de lire `km_arrivee` directement :

```php
public function getKilometrageActuelAttribute(): int
{
    return (int) (\App\Models\Trajet::getLastOdometer($this->id) ?? $this->mileage ?? 0);
}
```

### Bugs découverts sur `Proprietaires/Index.vue` et `Components/SearchFilter.vue` (hors périmètre des 5 parties, signalés en passant)
1. **`lodash` manquant** — `SearchFilter.vue` importe `debounce` depuis `lodash`, dépendance déjà identifiée comme manquante lors des tests de la Partie 3 (`npm install lodash`), à vérifier si toujours absente sur cette branche.
2. **Colonne `actions` non déclarée** — le tableau `columns` de `Proprietaires/Index.vue` ne contient pas d'entrée `{ key: 'actions', ... }` alors qu'un slot `#actions` est bien défini ; si `DataTable.vue` itère sur `columns` pour générer les colonnes, les boutons "Voir"/"Modifier" ne s'affichent jamais. Non confirmé, `DataTable.vue` jamais vu.
3. **🔴 Bug bloquant — filtre de recherche en 404** — `SearchFilter.vue` appelle `router.get(route().current(), ...)`. Or `route().current()` (Ziggy) renvoie le **nom** de la route active (ex. `"proprietaires.index"`), pas une URL. `router.get()` d'Inertia reçoit donc un nom de route à la place d'un chemin, d'où le 404. Correctif : `router.get(route(route().current()), ...)` (ajouter l'appel à `route()` pour transformer le nom en vraie URL), à appliquer dans `updateSearch` **et** `updateFilters`.
